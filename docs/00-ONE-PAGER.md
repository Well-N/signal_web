# 产品一页纸

## 产品名

**织讯 / SignalWeb**：一张会生长的 AI 资讯网络，一份每天能读完的判断简报。

## 一句话

织讯每天自动采集、去重和评分 AI 资讯，把同一事件的多篇报道聚成一个故事簇，用简报呈现结论，用关系网络看事件之间的联系，用爬虫页看抓取过程。

## 解决的问题

AI 资讯分散在官方博客、论文、GitHub、HN、Reddit 和媒体中；同一发布会反复出现；用户缺少“为什么重要”和“接下来关注什么”的判断。

## 核心组合

- **Horizon 式数据层**：多源采集、正文提取、Profile 评分、去重、投递。
- **DailyDawn 式编辑层**：每日重点、影响判断、待观察和行动清单。
- **蜘蛛可视化层**：蜘蛛在故事卡片之间移动，用蛛丝表示关系；阅读时可关闭。

## 三种视图

1. **简报**：今天先读什么，10 分钟完成。
2. **网络**：故事、来源、模型和公司如何关联。
3. **爬虫**：看每个来源抓了多少、是否失败，以及内容流向中央的过程。

## 首版范围

- 6–8 个 RSS/API 来源。
- 真实采集、URL/文本去重、故事聚类。
- `ai-news` Profile 的 0–10 评分和结构化摘要。
- 每日简报：Top 3、模型/产品、研究、工具、行业、待观察。
- Web 阅读界面和来源健康状态。
- 图谱与蜘蛛作为第二阶段增强，不阻塞数据闭环。

## 首版不做

- 全文镜像、绕过付费墙、自动转载。
- 公开注册和多租户计费。
- 浏览器扩展和桌面客户端。
- 文章内容触发任意工具或任意 URL 抓取。

## 成功标准

- 每天有 20–60 个有效故事簇，Top 10 基本没有重复事件。
- 每条摘要能追溯来源和原文。
- 来源、模型或提取失败时显示明确状态，不生成假数据。
- 简报核心阅读路径在 10 分钟内完成。

## 技术骨架

```text
Horizon（直接复用）
  → RSS/API → 正文提取 → 去重 → Profile 评分 → AI 日报
  → data/export/latest.json
  ↓
Next.js + shadcn/ui + react-force-graph-2d
  → 简报 / 详情 / 图谱 / 爬虫
```

MVP 先使用 Horizon 的文件输出和 JSON 导出，不另建数据库或独立 API 服务；需要多用户和历史检索时再升级到 Postgres + FastAPI。

## 里程碑

- M0：工程底座和 Docker。
- M1：4 个来源、列表和详情闭环。
- M2：评分、结构化摘要和简报。
- M3：故事聚类和图谱。
- M4：蜘蛛覆盖层和可访问性。
- M5：投递、备份和连续运行验收。

## 当前假设

个人优先、中文界面、单用户、单机可部署；公开网站和多用户能力在验证内容质量后再做。
