# 信息源与合规

## 1. 来源选择原则

首版优先选择机器可读、更新稳定、允许合理访问的来源：

1. 官方 RSS/Atom 或公开 API。
2. 有明确条款和限流的社区 API。
3. 只有在没有 RSS/API 且条款允许时才使用 HTML 抓取。

每个来源都必须有负责人、访问方式、计划频率、失败表现和关闭开关。未验证可用性的来源不加入生产配置。

## 3. 来源适配器契约

每个适配器实现：

```python
class SourceAdapter(Protocol):
    async def fetch(self, source: SourceConfig, client: httpx.AsyncClient) -> FetchResult: ...
```

`FetchResult` 包含：

- `items: list[RawItem]`
- `http_status`
- `etag` / `last_modified`
- `warnings`
- `error`（结构化错误码和可读信息）

适配器不得：

- 使用未配置的备用 URL。
- 在失败时返回示例/缓存新闻。
- 绕过登录、付费墙或验证码。
- 把完整正文写入日志。

## 4. 抓取礼仪

- 使用明确的 User-Agent，包含项目名和联系入口（可配置）。
- 支持 `ETag`、`If-Modified-Since`，减少重复下载。
- 默认并发不超过 4；单域请求间隔至少 1 秒；遵守 `Retry-After`。
- 404/410 不无限重试；429 按退避重试；5xx 有限重试后标记失败。
- RSS 只取最近 24–72 小时；不回溯整站。
- HTML 抓取只取列表页和必要正文，不并发扫全站。

## 5. 版权与内容使用

- 数据库保存标题、短摘要、元数据、原文链接和必要的引用片段。
- 不镜像全文、不提供全文下载、不重新发布图片。
- AI 摘要标明“由模型生成”，并附原文链接。
- 引用片段保持短小，且用于说明判断依据。
- 对明确禁止抓取或 AI 使用的来源，关闭接入。
- 删除来源时保留历史元数据的合规删除策略，按来源条款处理。

## 6. 去重与来源合并

### URL 去重

- 移除 `utm_*`、`fbclid`、`gclid`、fragment。
- 统一协议、主机大小写、默认端口和尾斜杠。
- 不把不同语言版本强行合并，除非模型确认事件相同。

### 内容去重

- 标题归一化后计算指纹。
- 短摘要/正文 SimHash 相似度高于阈值时标记候选重复。
- 同一 canonical URL 的多次采集只保留一个文章记录，更新 `last_seen_at`。

### 故事合并

- 同一事件允许多个来源，但只有一个主故事。
- 合并前检查实体、时间窗口、标题语义和来源关系。
- 相似主题但不同事件（例如同一公司的两个产品）不得合并。

## 7. 来源健康

每个来源记录：

- 最近成功时间。
- 最近错误码和错误摘要。
- 连续失败次数。
- 下次计划时间。
- 最近一次条目数。

连续失败达到阈值时，在设置页提示用户，不自动替换来源。

## 8. 合规检查清单

- [ ] 已确认访问方式（RSS/API/HTML）。
- [ ] 已阅读 robots.txt 和服务条款。
- [ ] 未绕过登录、付费墙、验证码或访问限制。
- [ ] 只保存必要元数据和短摘要。
- [ ] 原文链接可直接访问。
- [ ] 有来源关闭开关和删除策略。
- [ ] 失败时有可见提示。
