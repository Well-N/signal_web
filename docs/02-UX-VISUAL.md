# 交互与视觉规范

## 1. 视觉命题

织讯的画面像一张在夜间生长出来的编辑桌：深色背景上，新闻卡片是纸页，关系是细线，蜘蛛是正在阅读和采集的爬虫。它需要一眼看出“这条资讯和谁有关”，同时能迅速回到正常阅读。

视觉关键词：

- 深炭黑、暖白纸面、淡紫、青绿、珊瑚橙。
- 细网格、低对比噪点、少量发光，不做整屏霓虹。
- 信息密度高，但卡片留白清楚。
- 蜘蛛和蛛丝只作为导航辅助，文字始终是主角。

## 2. 页面布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ 织讯  今日 10/27  最后抓取 08:00  来源 8/8  搜索   简报 | 网络 | 列表 │
├─────────────┬──────────────────────────────────┬───────────────────┤
│ 今日摘要     │                                  │ 事件详情           │
│ 5 个故事     │          信息网络 / 新闻卡片       │ 标题  [8.7]        │
│              │                                  │ 来源与时间         │
│ 主题          │      ○──────○──────○             │ AI 摘要            │
│ 模型发布 12  │         ╲   🕷  ╱                │ 三条要点           │
│ 研究论文 18  │          ○────○                  │ 为什么重要         │
│ 工具  9      │                                  │ 原文与引用         │
│ 行业  7      │                                  │                   │
│              │                                  │                   │
│ 来源健康      │                                  │                   │
├─────────────┴──────────────────────────────────┴───────────────────┤
│ 时间轴：00  06  12  18  24    [过去 24h] [过去 7 天]               │
└────────────────────────────────────────────────────────────────────┘
```

桌面端采用三栏：左栏 240–280 px，右栏 360–420 px，中间自适应。窗口宽度低于 1100 px 时，左栏折叠为抽屉；低于 760 px 时只保留“列表/详情”阅读模式，图谱作为横向可滑动画布。

## 3. 三种视图

### 简报 Brief

默认首页，可读性优先。结构：

1. 今日一句话。
2. Top 3 信号：每条包含标题、分数、来源徽标、三行摘要和“为什么重要”。
3. 模型与产品更新。
4. 研究论文。
5. 开源与工具。
6. 行业、政策与社区。
7. 待观察清单。

简报不是 20 个长章节，而是 5–7 个短块。每块最多 4 个故事，更多内容用“展开全部”进入列表。

### 网络 Radar

发现关系的工作台。默认只显示故事簇，来源、实体和原始文章在点击后展开。

- 节点大小：故事重要性。
- 节点颜色：分类。
- 外圈徽标：来源数量/来源类型。
- 连线：同一事件、同主题、引用、共同实体。
- 新节点：轻微脉冲与“NEW”角标，不持续闪烁。
- 右上角提供“暂停蜘蛛”“降低动效”“干净模式”。

### 列表 Inbox

高效扫描。按时间、分数或来源排序；支持只显示未读、收藏、指定分类。列表与右侧详情联动，适合手机和快速浏览。

## 4. 信息网络编码

### 节点类型

| 类型 | 显示 | 默认可见 |
| --- | --- | --- |
| story（事件簇） | 圆形/胶囊，主节点 | 是 |
| source（来源） | 小方形徽标 | 展开后 |
| article（原文） | 小圆点 | 故事展开后 |
| entity（模型/公司/主题） | 标签节点 | 搜索或聚焦后 |

### 边类型

| 边 | 含义 | 视觉 |
| --- | --- | --- |
| `same_story` | 同一事件的多篇报道 | 实线，颜色随故事 |
| `similar` | 主题/语义相似 | 虚线，低对比 |
| `mentions` | 故事提到实体 | 细线，实体色 |
| `published_by` | 文章来自来源 | 短边/徽标列表 |
| `cites` | 文章引用另一篇文章 | 带箭头的细线 |

### 布局和防乱规则

- 默认最多显示 120 个故事节点；超过时按分类和时间做抽样。
- 实体节点默认折叠，避免一次显示几百个模型名。
- 每次刷新保持旧节点位置，只让新节点寻找空位。
- 同一事件的多篇文章不各自成节点，收进故事详情。
- 移动端默认显示列表；图谱改为“当前故事的局部关系图”。

## 5. 蜘蛛交互

### 角色

蜘蛛是“采集与阅读状态”的可视化，不是好的主要导航。它负责：

- 在新故事出现时从来源区走向新卡片。
- 在卡片标题上落脚，触发短暂高亮。
- 向相关故事、实体或来源牵出蛛丝。
- 在新故事被阅读后回到休息点。

### 技术表现

- 全屏透明 Canvas，`pointer-events: none`，不拦截卡片点击。
- 身体沿新闻卡片之间的安全路径移动，脚锚定卡片标题中的真实文字边界。
- 八条腿，两段式 IK；采用交替步态，脚偏移超过阈值时重新落点。
- 蛛丝是短生命周期的曲线，连接当前故事和关联故事；不超过 7 条同时存在。
- 高亮使用 CSS 临时 class 或 Canvas 叠加，不修改原文 DOM 文本。
- 页面滚动/卡片回流时重新测量锚点；找不到落脚点时停在卡片边缘，不强行拉扯。

### 禁止项

- 不撕下、克隆或覆盖页面真实文字。
- 不在用户阅读详情时遮住正文。
- 不让蜘蛛持续快速移动或闪烁。
- 不模仿参考项目的故障文字效果到影响可读性的程度。

## 6. 动效和可访问性

- 默认动效等级 `calm`：蜘蛛缓慢移动，蛛丝 1–2 秒淡出，新节点脉冲一次。
- `reduce-motion`：关闭步态和蛛丝，只保留卡片高亮；尊重系统 `prefers-reduced-motion`。
- 键盘：`Tab` 在卡片和筛选器之间移动，`Enter` 打开详情，`Esc` 关闭面板/菜单。
- 色彩不是唯一编码：分类同时显示文字标签和形状。
- 文本对比度至少 WCAG AA；深色画布上的正文使用暖白。
- 所有动画可暂停；页面失焦时停止渲染。

## 7. 组件规范

### 故事卡

- 标题最多两行，来源徽标、发布时间、分类、分数。
- 摘要首行用于列表，不展开全文。
- 多来源时显示“3 个来源”，点击展开来源列表。

### 详情面板

- 标题、评分、分类、时间。
- “一句话总结”“三条要点”“为什么重要”。
- 来源列表：来源名、原文标题、发布时间、抓取状态。
- 原文链接和引用片段。
- “AI 生成”标识、模型名、提示词版本、生成时间。

### 来源健康

每个来源显示：最近成功时间、最近失败原因、连续失败次数、下一次计划时间。失败不隐藏、不替换来源。

## 8. 空状态与错误状态

- 无数据：显示“今天还没有完成抓取”，并给出运行入口；不显示示例新闻。
- 单个来源失败：该来源标红但仍保留其他结果。
- AI 分析失败：故事保留“未分析”状态，展示原文信息；不生成占位摘要。
- 网络图谱无关系：显示“暂无关联”，不画装饰性的假连线。
- API Key 缺失：设置页明确提示，不执行模型请求。
