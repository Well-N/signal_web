# 决策记录

## ADR-001：先做 Web 应用

**决定：** 首版是单机可部署的 Web 应用，暂不做浏览器扩展或桌面壳。

**理由：** 资讯采集、存储和日报生成都在服务端；Web 端能同时覆盖桌面和手机阅读。浏览器扩展和 Tauri 桌面壳在数据层稳定后再评估。

## ADR-002：故事簇是图谱主节点

**决定：** 默认每个事件只显示一个故事节点，来源、文章和实体按需展开。

**理由：** 一篇文章一个节点会迅速形成不可读的毛线团；用户关心的是“发生了什么”，不是“有多少链接”。

## ADR-003：RSS/API 优先，HTML 抓取例外

**决定：** 首批来源只启用已确认的 RSS/API；HTML 抓取需要逐源审核，并遵守 robots.txt、条款和限速。

**理由：** RSS/API 更稳定，降低反爬和维护成本；HTML 选择器容易因改版失效。

## ADR-004：没有静默兜底

**决定：** 来源、正文提取、模型或数据库失败时显示明确状态；不使用假新闻、默认来源、默认模型或预置摘要替代。

**理由：** 本项目是资讯判断工具，静默兜底会破坏可信度。单源失败可以不让整批失败，但必须记录并显示 `partial`。

## ADR-005：Horizon 作为数据层参考，DailyDawn 作为编辑层参考

**决定：** 直接以 Horizon 作为后端底座，使用它的多源采集、Profile 评分、去重和投递；借用 DailyDawn 的编辑提示词和每日结构。

**理由：** Horizon 已经实现复杂的数据层；重新写一套只会增加维护成本。DailyDawn 更擅长把信号组织成可读日报。

**使用方式：** 复制/克隆 Horizon 到 `pipeline/`，保留 MIT 许可证；只新增 `ai-news` Profile 和 JSON 导出器。DailyDawn 只复制改编必要提示词，不同时运行两套调度器。

## ADR-006：蜘蛛是可选覆盖层

**决定：** 蜘蛛使用独立 Canvas 覆盖层，脚锚定新闻卡片文字，但在用户阅读时暂停；默认不修改正文。

**理由：** 参考项目的视觉冲击力来自“在文字上行走”，但直接撕字和持续抖动会损害阅读。蜘蛛应服务于导航和抓取状态。

## ADR-007：单用户优先

**决定：** 首版使用管理员 token，不做注册、计费和复杂权限；数据表预留 `workspace_id` 的扩展空间。

**理由：** 个人工具先验证内容质量和视觉体验，再考虑公开产品。

## ADR-009：文件优先，数据库后置

**决定：** MVP 直接读取 Horizon 的 `data/` 和导出 JSON，不先搭建 FastAPI、Postgres、队列或独立 worker。

**理由：** Horizon 已经是可运行的文件型流水线；首版需要验证内容和界面。只有出现多用户、复杂搜索、长历史或并发任务时才升级。

## ADR-010：图谱和蜘蛛使用现成库

**决定：** 图谱使用 `react-force-graph-2d`；蜘蛛首版使用 SVG + `motion` 路径动画。

**理由：** 不自研力导向布局和八腿 IK；先用最低成本验证视觉方向。无 LICENSE 的蜘蛛仓库只借鉴交互，不复制代码。

## ADR-008：简报采用短结构

**决定：** 每日简报为 Top 3 + 5 个分类块 + 待观察，不照搬 DailyDawn 的 20 个长章节。

**理由：** AI 资讯阅读需要快速扫描；深度内容按故事展开，不把日报写成一本电子书。

## 默认假设

- 产品名：织讯 / SignalWeb。
- 界面语言：中文优先。
- 时区：Asia/Shanghai。
- 每日简报：08:00。
- 首版只接 6–8 个来源。
- 首版只生成本地日报和 Web 看板；邮件/Webhook 作为 M1.5 可选。
- 公开网站、多用户、扩展和移动原生 App 暂不在首版。

## 待确认

- 最终是否公开给其他用户使用。
- 是否需要中文和英文双语简报。
- 是否已有可用的 LLM API/模型配额。
- 是否希望部署到云服务器，还是只在本机运行。
- 首批中文来源的授权和 RSS 可用性。
