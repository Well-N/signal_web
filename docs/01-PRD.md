# 产品需求文档

## 1. 产品定义

**织讯 SignalWeb** 是一个面向 AI 从业者、独立开发者和技术内容读者的资讯信号台。它每天把官方发布、研究论文、开源项目、技术社区和行业新闻汇入同一条流水线，先做去重和故事聚类，再用可配置的 Profile 评分和解释。

产品交付的不是“更多链接”，而是三层结果：

1. **今天发生了什么**：按事件聚合的资讯流。
2. **为什么值得看**：AI 摘要、判断依据、影响和不确定性。
3. **接下来关注什么**：每日简报、关键变化、待验证信号和行动清单。

## 2. 目标用户

### 主要用户

- 独立开发者和小团队技术负责人，需要快速判断模型、工具和基础设施变化。
- AI 产品经理、研究工程师和内容创作者，需要跨来源追踪同一事件。
- 每天愿意花 10–20 分钟阅读，但不想在多个订阅、社区和时间线之间来回切换的人。

### 非目标用户

- 需要毫秒级交易信号或金融投资建议的用户。
- 需要全文转载、批量下载受版权保护内容的用户。
- 需要大型企业级权限、审计和多租户计费的团队。

## 3. 核心问题

现有 AI 资讯消费有三个摩擦：

- **来源分散**：官方博客、arXiv、Hugging Face、GitHub、HN、Reddit 和中文媒体各自为政。
- **重复严重**：同一模型发布会被多家媒体改写，标题不同但事件相同。
- **缺少判断**：普通聚合器只排序，不解释“为什么重要”和“有哪些反证”。

织讯用“事件簇 + Profile 评分 + 编辑简报”解决这三个问题；图谱和蜘蛛负责让跨来源关系可见。

## 4. 产品原则

- 个人优先：首版按单用户自托管设计，避免过早引入账号和计费。
- 原文优先：摘要用于筛选，原文用于判断；所有 AI 内容带来源和生成标识。
- 可解释：评分、分类和摘要保存理由、模型、提示词版本和输入来源。
- 可关闭：蜘蛛动画、图谱动效、自动刷新都能独立关闭。
- 明确失败：来源不可用、正文提取失败、模型调用失败都进入可见状态，不伪造结果。

## 5. 关键使用场景

### 场景 A：早晨 10 分钟

用户打开“简报”视图，看到今日 Top 3 信号、模型/产品更新、论文、开源工具和行业动态；点击任意条目展开原文摘要和引用。

### 场景 B：追踪一个事件

用户搜索“某模型发布”，图谱把官方公告、媒体报道、论文、GitHub 仓库和社区讨论聚成一个故事簇；右侧显示时间线和来源可信度。

### 场景 C：发现关联

用户点击一个事件节点，蜘蛛沿关联线走向相关公司、模型或论文；侧栏显示“为什么它和当前事件有关”。

### 场景 D：验证 AI 判断

用户查看 AI 评分和摘要，看到引用的原文片段、模型名、提示词版本和生成时间；不满意时可以重新生成或隐藏 AI 结果，只保留原始信息。

## 6. 功能范围

### P0：首个可运行版本

- 6–8 个稳定来源的采集与定时运行。
- 统一字段、URL 规范化、内容指纹去重。
- 事件簇（Story）聚合，允许同一事件关联多条文章。
- `ai-news` Profile 的分类和 0–10 评分。
- 每条入选内容的结构化摘要：一句话、三条要点、为什么重要、标签、置信度。
- 每日简报：Top 3、模型/产品、研究、开源工具、行业与政策、待观察。
- Web 阅读界面：简报视图、时间线、事件详情、原文链接。
- 来源健康状态和失败提示。

### P1：可视化与检索

- 事件网络图，支持来源、实体和关系边。
- 蜘蛛覆盖层：在新闻卡片之间移动、落脚、牵出蛛丝。
- 搜索、主题/来源/时间筛选、收藏。
- 图谱与列表联动；暂停、降低动效、干净阅读模式。
- 每日邮件或 Webhook 推送。

### P2：增强能力

- 多语言简报（中/英）。
- 主题订阅与个性化权重。
- 历史趋势和“本周变化”对比。
- MCP 工具接口，让其他 AI 客户端查询和触发流水线。
- 浏览器扩展，把蜘蛛带到外部网页。

### 非目标

- 不自动复制全文、不绕过付费墙、不规避反爬限制。
- 不在首版做公开注册、评论、点赞和社交关系。
- 不让 LLM 直接抓取任意 URL 或执行文章中的指令。

## 7. 内容分类

第一版固定以下分类，后续由 Profile 配置扩展：

| 分类 | 典型内容 |
| --- | --- |
| `model-release` | 新模型、版本更新、能力/价格/上下文窗口变化 |
| `research` | 论文、基准、复现、数据集和技术报告 |
| `tooling` | 框架、Agent 工具、SDK、开发者基础设施 |
| `open-source` | GitHub 项目、开源模型、协议变化 |
| `industry` | 公司动作、融资、合作、监管与政策 |
| `community` | HN/Reddit/技术社区的高质量讨论和反证 |

## 8. 成功指标

首版不做虚荣指标，重点关注：

- 每日有效故事簇 20–60 个，Top 10 中重复事件不超过 1 个。
- 简报生成成功率 ≥ 95%；失败必须能看到具体来源和阶段。
- 用户从打开到读完 Top 3 的中位时间 ≤ 10 分钟。
- 详情页原文可追溯率 100%；AI 摘要引用依据可见。
- 图谱 100 个节点时保持 50–60 FPS；关闭动效后无持续动画开销。
- API 密钥不出现在前端响应、日志和导出文件中。

## 9. 版本假设

- 首版单用户、本地或单机服务器部署。
- 界面默认中文，数据结构保留 `language` 字段。
- 默认每天 08:00（Asia/Shanghai）生成简报，可由环境变量修改。
- 信息来源以 RSS/API 为主；HTML 抓取只用于明确配置且允许访问的页面。
