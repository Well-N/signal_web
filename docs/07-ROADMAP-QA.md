# 路线图与验收

## 1. 交付策略

先交付一条真实可运行的纵向切片：真实来源 → 真实评分 → 真实简报 → 可读界面。图谱和蜘蛛在数据链路稳定后接入，避免先做漂亮空壳。

**实现顺序以 [10-BUILD-PLAN](10-BUILD-PLAN.md) 为准：直接复用 Horizon 作为后端底座，借用 DailyDawn 的编辑提示词，前端用现成框架和图谱库。下面的 M0–M5 是能力目标，不是要求从零重写。**

## 2. 里程碑

### M0：工程底座（2–3 天）

- 克隆 Horizon 到 `pipeline/`，先按原项目跑通一次真实采集。
- 保留 Horizon 的许可证、README、测试和现有来源适配器。
- 建立 `web/` 目录和前端骨架。
- 增加 `data/export/latest.json` 的最小导出器。

验收：`uv run horizon --hours 24` 能生成真实 Markdown；导出器能生成 JSON；空数据不会产生示例新闻。

### M1：采集与阅读闭环（第 1 周）

- 直接在 Horizon 配置中接入 4 个来源：HN、arXiv、Google News RSS、一个官方博客 RSS。
- 复用 Horizon 的 URL 去重、全文提取和运行日志。
- 新增 `ai-news` Profile，不重写抓取器。
- 完成列表视图、故事详情和原文链接。

验收：一次真实运行至少产生 20 条文章；同一 URL 不重复入库；单源失败时其他来源继续，但失败可见。

### M2：Profile 评分与摘要（第 2 周）

- 在 Horizon 的 `profiles/ai-news/` 中配置 0–10 评分和结构化摘要。
- 复用 Horizon 的 AI client、缓存/重试和 enrichment 流程。
- 用 DailyDawn 的 editor/expert 提示词改编 Top 3 和编辑口吻。
- 完成简报视图的 Top 3 和分类块。

验收：Top 10 中重复事件不超过 1 个；摘要的每条引用都能在原文中找到；API Key 不出现在浏览器响应和日志中。

### M3：故事聚类与信息网络（第 3 周）

- 复用 Horizon 的跨源去重和 topic dedup；需要时再补 embedding/实体关系。
- 完成故事簇合并、主文章选择和跨源来源列表。
- 用 `react-force-graph-2d` 渲染图谱，不自研力导向引擎。
- 首版图谱先做稳定布局和少量动效。

验收：100 个故事节点可交互；同一事件只出现一个主节点；相似主题不被错误合并；图谱无数据时显示空状态。

### M4：蜘蛛视觉层（第 4 周）

- 用 SVG 蜘蛛 + `motion` 沿卡片路径移动，不做首版八腿 IK。
- 用 SVG 曲线画蛛丝，叠加在页面之上，`pointer-events: none`。
- 实现暂停、关闭、`prefers-reduced-motion` 和详情阅读自动暂停。
- 完成桌面端和窄屏降级。

验收：蜘蛛不遮挡主要文字、不拦截点击；关闭动效后无持续 `requestAnimationFrame` 负载；页面滚动和卡片变化时不出现脚被拉扯到页面外的错误。

### M5：交付与运维（第 5 周）

- 每日简报定时生成、邮件或 Webhook 投递。
- 备份、日志轮转、来源健康页、错误恢复。
- 真实 API 多轮验收；部署文档和演示数据边界说明。

验收：连续运行 7 天无人工干预；每天有可用简报或明确失败原因；重启后不重复发送已发送简报。

## 3. 任务拆分

### 后端

- [ ] 项目脚手架、配置加载、结构化日志。
- [ ] SourceAdapter 与 4 个首批适配器。
- [ ] 规范化、URL 去重、内容指纹。
- [ ] 数据库迁移和运行状态机。
- [ ] LLMProvider 抽象、JSON 校验、缓存。
- [ ] Profile registry 和提示词版本。
- [ ] Story 聚类、实体提取、图谱边生成。
- [ ] Brief 生成和投递接口。

### 前端

- [ ] 设计 token、深色画布、编辑风组件。
- [ ] 简报、列表、详情、来源健康。
- [ ] 搜索与筛选。
- [ ] 图谱节点/边渲染和局部展开。
- [ ] 蜘蛛 Canvas 覆盖层、暂停/降低动效。
- [ ] 空状态、错误状态、键盘导航。

### 内容与数据

- [ ] 验证首批来源的条款、feed/API 可用性。
- [ ] 定义 `ai-news` 评分样例和人工标注集。
- [ ] 建立 50 条真实来源 fixture（明确标注来源和采集日期）。
- [ ] 审核 Top 3 和日报编辑规则。

## 4. 测试矩阵

| 层级 | 测试 | 通过标准 |
| --- | --- | --- |
| 单元 | URL 规范化、去重、分数边界、JSON 校验 | 边界输入稳定；失败明确 |
| 契约 | 每个 SourceAdapter 的 fixture | 条目字段完整；错误码可读 |
| 集成 | 从 fixture 到故事和简报 | 无重复主故事；失败不伪装成功 |
| API | 列表、详情、图谱、管理运行 | 权限、分页、空状态正确 |
| E2E | 真实来源运行 → 简报 → 详情 | 关键路径可完成 |
| 视觉 | 1440/1024/390 宽度 | 无溢出、遮挡、不可点击区域 |
| 性能 | 100 节点图谱、60 秒蜘蛛 | 50–60 FPS；关闭后无持续渲染 |
| 安全 | SSRF、HTML 清洗、密钥泄漏、提示注入 | 全部阻断 |
| 稳定性 | 单源失败、模型 429/500、数据库重启 | 有可见状态；可恢复 |

## 5. Definition of Done

一个功能完成需要同时满足：

- 文档中的行为已实现。
- 有对应的真实数据或明确 fixture 测试。
- 错误路径有 UI 状态和日志。
- 不引入隐藏默认来源、假摘要或未授权抓取。
- 代码通过格式检查、类型检查和测试。
- 文档和变更记录同步更新。

## 6. 首个演示脚本

演示只使用真实采集结果：

1. 手动运行一次采集。
2. 展示部分来源失败但其他来源继续。
3. 打开简报，展示 Top 3 和原文链接。
4. 打开一个跨源故事，展示 3 个来源和合并理由。
5. 切换到网络视图，展示事件和实体关系。
6. 开启蜘蛛，点击另一条故事，展示蛛丝和详情联动。
7. 关闭动效，确认阅读模式仍完整可用。
